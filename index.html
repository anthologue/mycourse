Why We Need Inheritance

Real programs often need to represent several kinds of objects that are mostly alike. Take a library system: it might serve two types of members, students and staff. Both need a name, an ID, a department, and a borrowing quota — but a student also has a class group, and a staff member has a designation.

The Naive Approach

The most straightforward way to model this is to write a separate class for each kind of member, giving each one every field it needs:

public class Student {
    private String name;
    private String id;
    private String department;
    private int quota;
    private String studentClass;
}

public class Staff {
    private String name;
    private String id;
    private String department;
    private int quota;
    private String designation;
}

It works, but look closely: four of the five fields in Student and Staff are identical. Any shared behavior — like a method to set these basics or check the quota — would have to be written and maintained twice.

Recap
  • Related classes often share most of their data and behavior.
  • Writing each class independently duplicates that shared part.
  • Duplication makes the code harder to keep consistent as it grows.

Superclasses and Subclasses

A more efficient way is to pull every shared characteristic into one class, called a superclass, and let the more specific classes build on top of it as subclasses. For the library example, that shared class is Member: it holds the name, ID, department, and quota that every member needs, along with the methods that work on them.

Defining the Superclass

public class Member {
    private String name;
    private String id;
    private String department;
    private int quota;

    public void setBasics(String name, String id, String department) { ... }
    public void setQuota(int quota) { ... }
    public int getQuota() { ... }
}

Extending It

Student and Staff then become subclasses of Member using the extends keyword, and each only needs to declare the one field that makes it different:

public class Student extends Member {
    private String studentClass;
}

public class Staff extends Member {
    private String designation;
}
Recap
  • A superclass (or "parent class") holds characteristics common to several related classes.
  • A subclass (or "child class") is defined with extends.
  • Each subclass keeps only what makes it unique — the rest lives in the superclass, once.

What Gets Inherited

Once Student and Staff are defined as subclasses of Member, they automatically inherit every attribute and method that Member defines — nothing needs to be redeclared. On top of that inherited set, each subclass still has the individual fields it defined for itself.

Using an Inherited Method

Even though setBasics and setQuota are written in Member, they're called directly on a Student object:

Student student = new Student();
student.setBasics("Alice", "S1001", "IT");  // inherited from Member
student.setQuota(5);                         // inherited from Member
// studentClass is unique to Student, not part of Member

The same is true for a Staff object — it reuses those same inherited methods, while designation stays specific to Staff.

Recap
  • A subclass automatically has all of its superclass's attributes and methods.
  • Inherited members are used as-is, with no need to rewrite them.
  • A subclass can still add attributes and methods that are entirely its own.
  • This is how inheritance removes the duplication seen in the naive approach.
